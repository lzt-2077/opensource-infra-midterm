## 2. Q1 的三列模型

**三列 = 法人类型 × 组织形态 × 财政赞助**，三个维度正交，**不能相加**。

- 标签来源：`命名空间-主体-订正版.csv` 的级联规则（溯源总表 B 级，规则见 `43` 号），**不是** 293 条人工字典。
- 人工核验：`主体字典-人工.csv` 293 条，覆盖 **40.4%** 入边（底基 50.7%）。
- 级联覆盖：**87%** 入边；其余 12.75% 记「未知」，不推测。
- 主输出：`作业/整合/三列模型-主图口径-透视.csv`；底基：`Q1-底基三列.csv`。
- 脚本：`作业/整合/三列模型-重建.py`、`Q1-三列模型.py`。

| 容易报错的数 | 正确值 |
|---|---|
| 公司占全库入边 | 4.51%（剔除命名空间内部边后 **2.70%**） |
| 公司占底基入边 | 1.4%（按包数不加权：16/319 = **5.0%**） |
| 项目组织中被非营利托管 | 6,026 / 490,016 = **1.23%**（不是 1,615/0.15%） |
| 底基入边合计 | 735,511（316 个可匹配，覆盖 99.6%） |

## 3. Q2 的两套标签

同一批 8,175 个「有公司参与」的包（`corp_share > 0`，中位仅 5.6%，是很松的定义）：

| 标签 | 「有公司账号」的包 | 代持比例 |
|---|---|---|
| 账号级（`主体分类-全量.csv`，190 个公司账号） | 483 | **94.1%**（正文口径） |
| 命名空间级（`包-账号-主体.parquet` 的 `法人类型`；公开仓库不含） | 1,237 | **84.9%**（下界） |
| 至少命中一种 | 1,351 | 两者都无 83.5% |

阈值敏感性（corp_share 0.2 / 0.5 / 0.8）：93.7% / 93.2% / 95.4%。

**不要**把 94.1% 解释成「隐瞒所有权」；它只说「公司员工有提交的包里，公司组织账号几乎不出现」。

## 4. 底基与稳定性

- θ(t) = 366 × (N(t) / N(2025-12))^0.5；底基 = { 入度 ≥ θ(t) }。
- 2015-01：5 个（1.23%）；2025-12：319 个（0.18%）。
- α=0.5 是五档扫描的选择，不是推导。
- 月度成员变动率 **0.27%**（`75-底基序列-主图.csv`）；Jaccard 中位 0.978。
- 排名规则 4.39% / 88.94%、聚类 ARI 0.570/0.584/0.620 是**会话内实验（B 级，无脚本）**，引用时必须标注。

## 7. 答辩五问的答案

1. **94.1% 依赖标签源吗？** 依赖。账号级 483 个 → 94.1%；命名空间级 1,237 个 → 84.9%；两者都无 83.5%。正文用账号级，84.9% 作下界。
2. **项目组织里到底多少有非营利托管？** 6,026 / 490,016 = 1.23%（CNCF/LF 6,025 + NumFOCUS 1）。1,615 只是「法人类型=非营利 × 项目组织」那一格。
3. **底基按包数公司占多少？** 16/319 = 5.0%；按入边加权 1.4%。加权值回答「流量流向谁」，包数回答「有多少个包」。
4. **ARI 的脚本在哪？** 没有。溯源总表标 B 级（会话内实验）。底基序列、N90、Q1、Q2 的头条数字是 A 级。
5. **171,730 与 174,800 差的 3,070 个包去哪了？** 融合表行全集取自位置表，与主图包集合不完全重合；两者不能互相替代（报告 §3.1）。
